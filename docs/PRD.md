# 產品需求文件 (PRD) - 校園二手書交換平台

## 1. 專案概述
### 1.1 背景與動機
在大學求學期間，教科書往往是學生一筆沉重的經濟負擔。每學期購入的新書在學期結束後便被閒置，造成資源浪費；而新生或有需要的同學卻往往因為管道不透明或高昂的價格，難以取得所需的參考書。
本專案「校園二手書交換平台」旨在為大學生打造一個專屬、安全且高效的二手書流轉生態系統。透過精準搜尋、書況透明化與校園面交機制，不僅能協助舊書找到新主人，實現資源循環，也能有效降低學生的求學成本。

### 1.2 目標用戶
- **買家/交換者（一般大學生）**：希望以低成本取得教科書、參考書或小說，偏好在校園內方便地面交。
- **賣家/分享者（一般大學生）**：希望出清不再使用的書籍，變現或交換其他實用書籍，清空書櫃空間。
- **系學會或社團**：定期舉辦二手書展、舊書交換活動的團體，需要一個平台來展示與媒合書籍。

### 1.3 核心價值主張
- **安全與信任**：限用學校網域信箱註冊認證，確保平台使用者均為同校師生，降低詐騙風險。
- **極簡面交**：排除複雜的線上金流與物流，統一採用校園現場面交、一手交錢一手交貨，符合學生習慣。
- **書況完全透明**：透過多照片上傳與標準化書況描述，配合問答留言板，消除買賣雙方的資訊不對稱。
- **精準尋書**：支持 ISBN、科目與系所的精確篩選，讓學生能在三秒內找到下學期必修課的指定用書。

## 2. 功能需求
系統共包含五大核心功能模組，以下詳細說明每個模組的使用者故事與功能明細：

### 2.1 書籍上架系統 (F-01)
- **使用者故事**：
  > **作為** 一名想出清舊書的學生，**我希望** 能夠輕鬆地上傳書籍照片、設定合理的價格或標記為交換，並詳細填寫書籍的書況，**以便** 潛在的買家能清楚評估並與我聯繫。
- **功能明細**：
  - **書籍基本資訊輸入**：書名、作者、出版社、ISBN。
  - **價格/交換模式設定**：可選擇「販售模式」（填寫價格，如：$150）或「交換模式」（標註僅限交換，並可填寫期望交換的書單/類型）。
  - **書況透明化勾選**：
    - 書況評級（全新 / 接近全新 / 輕微劃記 / 劃記繁多 / 書頁破損或缺頁）。
    - 備註說明（例如：有折角、無泡水、附隨書光碟等）。
  - **多相片上傳**：支援上傳至多 3 張書籍實拍照片（封面、書脊、內頁劃記處）。
  - **系所與科目關聯**：可下拉選擇適用系所（如：資工系、企管系）與手動輸入科目名稱（如：演算法、經濟學）。

### 2.2 分類檢索功能 (F-02)
- **使用者故事**：
  > **作為** 一名急需課堂教科書的新生，**我希望** 能透過「系所」、「科目名稱」或「ISBN」進行快速且精確的搜尋與篩選，**以便** 我能以最快速度找到符合課程要求的二手書。
- **功能明細**：
  - **關鍵字全域搜尋**：支援書名、作者、出版社之關鍵字搜尋。
  - **進階條件篩選**：
    - **按系所篩選**：依據學院與系所層級進行分類篩選。
    - **按科目名稱搜尋**：精確或模糊匹配課程科目。
    - **ISBN 搜尋**：輸入 10 碼或 13 碼 ISBN，精確查找同款教科書，避免買錯版本。
  - **狀態過濾**：可過濾僅顯示「上架中」的書籍，隱藏已被預約或成交的項目。
  - **排序機制**：支援「價格由低到高」、「最新上架」等排序。

### 2.3 預約請求系統 (F-03)
- **使用者故事**：
  > **作為** 一名看到心儀教科書的買家，**我希望** 能向書主送出交換或購買的預約請求，**以便** 系統自動通知書主，並開啟後續的面交聯繫。
- **功能明細**：
  - **送出請求**：點擊書籍詳情頁的「發送預約請求」，可填寫簡短留言（例如：預期面交時間、欲交換的書籍）。
  - **系統自動通知**：
    - 當收到預約時，書主的個人中心會收到即時提示（紅點或通知訊息）。
    - 系統自動產生一組「面交確認單」，方便雙方追蹤。
  - **請求狀態流轉**：
    - 買家送出請求 -> 狀態變更為「已預約/處理中」。
    - 書主可選擇「接受」或「拒絕」此請求。
    - 若書主「接受」，則書籍狀態轉為「已預約」，並向買家顯示書主的聯絡資訊（如信箱、Line ID 等）。
    - 若「拒絕」，書籍恢復「上架中」狀態。

### 2.4 個人書櫃管理 (F-04)
- **使用者故事**：
  > **作為** 一名賣家，**我希望** 能在一個專屬頁面查看自己所有上架書籍的當前狀態，並能隨時進行編輯修改或下架，**以便** 我能高效管理我的二手書存貨與交易進度。
- **功能明細**：
  - **狀態分頁展示**：
    - **上架中**：目前公開展示、等待買家預約的書籍。
    - **已預約**：已被買家送出請求且已被接受，進行面交準備中的書籍。
    - **已成交**：已順利完成面交，不再對外公開展示的書籍歷史紀錄。
  - **書籍資訊編輯**：支援對「上架中」的書籍修改價格、補充書況照片或說明。
  - **下架功能**：若書籍已在其他管道售出，可隨時一鍵下架。
  - **一鍵確認成交**：面交完成後，書主點擊「確認成交」，系統將書籍移至「已成交」分類。

### 2.5 即時留言/私訊系統 (F-05)
- **使用者故事**：
  > **作為** 一名對某本二手書有興趣的學生，**我希望** 能在書籍詳情頁下方的留言板進行公開發問，**以便** 在面交前先向書主確認詳細書況（如：是否有最新版光碟、第幾章有筆記等）。
- **功能明細**：
  - **書籍詳情留言板**：開放式的留言詢問區，所有使用者皆可查看留言內容。
  - **即時回覆功能**：書主可針對特定留言進行直接回覆，回覆會層級式（Thread）顯示於該留言下方。
  - **通知機制**：當有人在自己的書籍下留言，或是書主回覆了自己的發問時，系統會於通知中心發送提醒。
  - **隱私防護**：留言板禁止輸入敏感個人資訊（如手機、身分證字號），提示使用者待預約接受後再進行私密聯絡。

## 3. 非功能需求

### 3.1 技術限制
- **開發框架**：後端採用 **Flask** 微框架，前端 template 採用 **Jinja2** 模板引擎。
- **資料庫**：採用 **SQLite** 關聯式資料庫，便於開發、測試與輕量級部署。
- **無外部複雜金流/物流**：平台不串接綠界、LINE Pay 等線上支付，亦不支援超商物流，純粹作為資訊媒合平台，交易方式固定為「校園現場面交、現金或當場轉帳」。

### 3.2 效能與安全考量
- **響應時間**：分類檢索與關鍵字搜尋必須在 **1 秒內** 完成檢索並回傳結果（資料庫索引優化、靜態資源快取）。
- **安全防護與註冊限制**：
  - **學校網域信箱限制**：註冊帳號時，系統檢核信箱後綴必須為特定學校網域（例如：`*.edu.tw`），並需通過信箱驗證碼驗證方能開通帳號。
  - **防 SQL 注入**：所有資料庫操作均使用 ORM (SQLAlchemy) 或參數化查詢。
  - **密碼安全**：密碼必須以雜湊加密（如 Werkzeug pbkdf2_sha256）儲存，嚴禁明文存放。

### 3.3 使用者介面與體驗 (UI/UX)
- **設計風格**：採用**簡潔卡片式設計** (Clean Card-based UI)，讓書籍資訊像精美的圖書館藏卡一樣呈現，降低視覺疲勞。
- **響應式網頁設計 (RWD)**：必須完美適應手機、平板與電腦螢幕，方便學生在校園中直接拿著手機操作。
- **微互動**：懸停卡片時的微幅放大、按鈕點擊時的平滑過渡，營造現代、高質感的介面氛圍。

## 4. MVP 範圍 (Minimum Viable Product Scope)

為了能快速上線測試並收集學生反饋，我們將功能劃分為以下優先順序：

| 優先級 (Priority) | 功能模組 | 具體功能描述 |
| :--- | :--- | :--- |
| **Must Have (核心必備)** | **F-01 書籍上架** | 支援基本資訊填寫、價格與書況評級勾選、1 張封面相片上傳。 |
| | **F-02 分類檢索** | 支援依系所選單篩選、ISBN 與關鍵字搜尋，1 秒內回傳。 |
| | **會員認證系統** | 限用 `edu.tw` 信箱註冊、驗證與基本登入/登出。 |
| | **F-04 個人書櫃** | 顯示「上架中」、「已預約」與「已成交」狀態，支援下架與編輯。 |
| **Should Have (應該要有)** | **F-03 預約請求** | 買家一鍵發送預約，書主可在個人書櫃接受/拒絕，接受後顯示聯絡方式。 |
| | **F-05 即時留言** | 書籍詳情頁下方的留言問答板，供雙方在面交前溝通。 |
| | **照片多張上傳** | 支援上傳至多 3 張書況細節照片。 |
| **Nice to Have (有更好)** | **我的收藏功能** | 學生可先將心儀書籍加入「追蹤清單」，方便後續對比。 |
| | **系統內即時私訊** | 不用揭露信箱或 Line，直接在平台內進行一對一即時聊天室對話。 |
| | **熱門書籍排行** | 根據瀏覽量與搜尋頻率，展示目前校園最搶手的教科書。 |
