# 產品需求文件 (PRD) - 校園二手書交換平台

## 1. 專案概述

### 背景與動機
在大學求學期間，每學期的教科書與參考書費用高昂，對許多學生而言是一筆不小的經濟負擔。然而，學期結束後，這些書籍往往處於閒置狀態，缺乏有效的再利用管道。現有的二手書交易平台多偏向通用型，缺乏針對校園情境（如：依系所、科目搜尋）的優化，且常涉及繁複的金流與物流手續。
本專案旨在打造一個專屬校園的「二手書交換與買賣平台」，透過精準的學術分類搜尋、透明的書況揭露以及校園當面交貨（面交）機制，簡化二手書的流轉流程，降低大學生取得教科書的成本，同時實踐資源循環。

### 目標用戶
1. **一般大學生**：
   - 買方：希望以低成本取得課堂指定教科書或參考書的學生。
   - 賣方：手中有閒置教科書、想要清理空間或回收部分購書成本的學生。
2. **系學會或社團**：
   - 希望舉辦舊書義賣、二手書交換活動的校園組織。

### 核心價值主張
- **省時省力**：提供「系所」、「科目名稱」、「ISBN」的精確搜尋，讓學生快速定位所需書籍。
- **安心交易**：限學校網域信箱註冊認證，確保交易雙方均為同校學生，並採校園面交，免去詐騙與物流糾紛。
- **書況透明**：詳細的書況描述與照片上傳，並設有即時留言板供買賣雙方在面交前溝通細節。

## 2. 功能需求

### F-01 書籍上架系統
- **功能描述**：提供使用者將閒置書籍上架至平台的介面。
- **功能細節**：
  - 上傳書籍照片（支援多張上傳，至少一張封面照）。
  - 設定交易類型與價格：可選擇「買賣（設定金額）」或「僅限交換」。
  - 填寫詳細書況：包括有無劃記、折損、汙損程度、版本年分等。
- **使用者故事 (User Stories)**：
  - 作為 **賣方/交換方**，我希望 **能夠輕鬆上傳書籍照片並填寫價格與書況**，以便 **讓有興趣的買方能快速了解書籍的實際狀況**。

### F-02 分類檢索功能
- **功能描述**：提供買方快速且精準尋找目標書籍的搜尋與篩選機制。
- **功能細節**：
  - 支援依「系所」（例如：資工系、企管系）進行分類篩選。
  - 支援輸入「科目名稱」（例如：微積分、資料結構）進行關鍵字搜尋。
  - 支援輸入「ISBN」進行精確篩選，確保版本完全一致。
- **使用者故事 (User Stories)**：
  - 作為 **買方**，我希望 **能夠透過系所、科目名稱或 ISBN 搜尋書籍**，以便 **快速找到下學期課堂上指定的特定教材**。

### F-03 預約請求系統
- **功能描述**：促成買賣雙方建立交易意向的對接系統。
- **功能細節**：
  - 買方在書籍詳情頁可點擊「送出預約/購買請求」。
  - 系統自動通知書主（透過站內通知/電子郵件）。
  - 書主可查看預約清單，並決定接受或拒絕請求。一旦接受，系統將提供雙方彼此的聯絡資訊（如信箱或通訊軟體 ID）以進行後續面交聯繫。
- **使用者故事 (User Stories)**：
  - 作為 **買方**，我希望 **可以直接對心儀的書籍發起預約請求**，以便 **在不透露過多隱私的情況下向書主表達交易意向**。
  - 作為 **賣方**，我希望 **在有人預約我的書籍時收到即時通知**，以便 **我能快速回覆並確認交易**。

### F-04 個人書櫃管理
- **功能描述**：提供使用者管理自己上架書籍與交易狀態的控制台。
- **功能細節**：
  - 書籍狀態分類：清晰區分「上架中」、「已預約（處理中）」與「已成交（下架）」。
  - 支援編輯功能：允許使用者隨時修改未成交書籍的價格、描述或照片。
  - 支援手動下架/標記成交功能.
- **使用者故事 (User Stories)**：
  - 作為 **書籍擁有者**，我希望 **有一個個人書櫃面板來管理我所有上架的書籍**，以便 **隨時掌握交易進度、修改書籍資訊或將已成交的書籍下架**。

### F-05 即時留言/私訊系統
- **功能描述**：在交易確定前，提供買賣雙方公開或私下的溝通管道。
- **功能細節**：
  - 書籍詳情頁下方設有「問與答/留言板」，允許有興趣的買家公開留言詢問。
  - 書主可直接針對留言進行回覆，且其他使用者亦可檢視回覆內容（避免重複詢問相同問題）。
- **使用者故事 (User Stories)**：
  - 作為 **潛在買方**，我希望 **能在書籍頁面下方留言詢問書主詳細書況（例如：有沒有缺頁、第幾版）**，以便 **在決定預約前進一步確認是否符合需求**。

## 3. 非功能需求

### 技術限制與框架
- **後端框架**：Flask (Python 3.x)
- **前端樣板引擎**：Jinja2 (搭配 Vanilla CSS 進行精緻、具現代感的卡片式與響應式 RWD 設計)
- **資料庫**：SQLite (單一檔案，易於部署與測試)

### 效能考量
- **響應時間**：分類檢索與搜尋功能在資料量 10,000 筆以內時，搜尋結果必須在 1 秒內回傳完成。
- **圖片處理**：上傳之書籍圖片需於後端進行壓縮與格式最佳化，以減少資料庫儲存負擔與加快網頁載入速度。

### 安全與存取考量
- **身分驗證**：註冊帳號限制必須使用學校網域信箱（例如 `*.edu.tw`），且需進行信箱驗證。
- **隱私保護**：非交易雙方（未被接受預約者）無法取得使用者的聯絡信箱或通訊軟體聯絡方式。
- **資料庫安全**：使用者密碼需採用雜湊加密（如 `werkzeug.security` 的 `generate_password_hash`）後儲存。

### 介面設計 (UI/UX)
- 採用**簡潔現代的卡片式設計 (Card-based Layout)**，每本書籍以卡片形式呈現，包含封面照、價格/交換標籤、科目與系所。
- 採用和諧的校園活力色調（如森林綠、學院藍等），並搭配平滑的 Hover 微動畫，提升操作的精緻感。
- 完全支援行動端瀏覽器（Responsive Web Design），方便學生在校園中以手機隨時查看與聯繫。

## 4. MVP 範圍

為了快速驗證核心價值並在最短時間內推出上線，功能區分如下：

| 功能模組 | Must Have (MVP 核心) | Should Have (建議開發) | Nice to Have (未來擴充) |
| :--- | :--- | :--- | :--- |
| **帳號認證** | 註冊、登入、學校網域信箱檢查 | 信箱驗證碼啟用機制 | 結合 OAuth 學生證第三方登入 |
| **書籍上架** | 上傳單張封面圖、設定價格、填寫書況 | 多張圖片上傳、ISBN 自動帶出部分書訊 | 掃描條碼自動上架 |
| **分類檢索** | ISBN/科目關鍵字搜尋、系所下拉選單篩選 | 依「上架時間」、「價格高低」排序 | 依「使用者目前定位與距離」排序 |
| **預約交易** | 送出預約請求、賣方接受/拒絕、顯示聯絡方式 | 系統自動發送 Email 預約通知 | 站內即時 Chat room 私訊功能 |
| **書櫃管理** | 查看上架中/已預約/已成交狀態、手動標記成交 | 編輯上架書籍資訊、一鍵重新上架 | 書籍曝光度分析、推廣置頂 |
| **留言互動** | 書籍頁面公開留言與回覆 | 檢舉不良留言與過濾敏感詞彙 | 留言按讚、標記特定使用者 (@username) |
